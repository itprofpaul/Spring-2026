
Assignment: Build a Wordle-Style Game

Create a new page on your GitHub Pages site that lets a player guess a hidden word using keyboard input, game states, and clean JavaScript structure.
Assignment Goal

Build a browser-based word guessing game inspired by Wordle using HTML, CSS, and JavaScript. Your game should run as a new page on your existing GitHub Pages site.

This assignment is designed to bring together the major ideas from this module:

    game loops and repeated updates
    timers or limited repeated actions when appropriate
    keyboard input
    state machines such as playing, win, and lose
    clean separation between UI code and logic code

What You Are Building

You will create a game where the player tries to guess a hidden word one row at a time.

Your game should include:

    a visible grid of guesses
    keyboard input from the player
    a hidden target word
    feedback after each guess
    a win state if the player guesses correctly
    a lose state if the player runs out of guesses
    a restart option

Core Requirements

    Use your existing GitHub Pages site
    Create a new page for the assignment
    Use HTML, CSS, and JavaScript only
    Create a playable Wordle-style game
    Use keyboard input for letters
    Allow the player to submit a full guess
    Show feedback for each letter after a guess
    Track the game state with values such as playing, win, and lose
    Prevent more input after the game ends
    Include a restart button or restart method
    Separate UI rendering from game logic as much as possible
    Deploy the finished page to GitHub Pages

Game Rules for This Assignment

Use these rules unless your instructor approves a variation:

    The hidden word should be 5 letters long
    The player gets 6 guesses
    The player types one letter at a time
    Backspace removes the last typed letter in the current row
    Enter submits the guess only when the row has 5 letters
    After submission, each letter should receive feedback

Suggested feedback colors:

    Green: correct letter in the correct position
    Yellow: correct letter in the wrong position
    Gray: letter is not in the target word

```
Step 6: Process Letters, Backspace, and Enter

Your logic should handle three main input cases:

    letter keys add a letter to the current row
    Backspace removes the last letter
    Enter submits the row when it has 5 letters

Helpful rule:

    ignore input if the game is not in the playing state
    ignore extra letters once a row already has 5 characters

Step 7: Check the Guess Against the Target Word

When the player presses Enter, compare the current guess to the target word.

For each letter, determine whether it is:

    correct and in the correct place
    correct but in the wrong place
    not in the word

You can store that result in a separate structure for later rendering.
```

```
Step 8: Update the Game State

After evaluating the guess:

    set the state to win if the guess matches the target word
    move to the next row if the guess is wrong and guesses remain
    set the state to lose if the player used the final row without solving it

if (guess === game.targetWord) {
```

game.state = "win";
} else if (game.currentRow === 5) {
game.state = "lose";

Hints and Advice

    Start with a fixed target word before trying random words.
    Get the board display working before worrying about colors.
    Keep your logic functions separate from your rendering functions.
    Use console.log() during development to inspect state changes.
    Finish the core playable version first, then improve visuals.
    Do not try to do everything in one giant function.
